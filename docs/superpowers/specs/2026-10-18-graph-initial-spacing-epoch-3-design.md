## 2. Remediation design

### A. Separate headless-safe accessibility tests from actual-window tests

The only display-dependent methods in `AccessibleGraphCanvasShould` are `receiveTabThroughSwingDispatchAndRestoreFocusTraversalConfiguration` and `ignoreEnterForSelectionsAbsentFromCurrentVisibleOrderAfterStateReplacement`; both call `withFocusedCanvas`, which creates and shows a `JFrame`. Add the repository's existing JUnit assumption pattern to those two methods, before constructing the frame: skip when `GraphicsEnvironment.isHeadless()` is true, and run their existing focus/traversal assertions unchanged when a display is available. Do not skip the rest of the class, weaken assertions, or replace the real-window test with a mocked focus owner.

The method-level headless receipt must show exactly those two methods skipped and the other nine methods executed and passed. In the full module receipt these are the only two newly permitted skips: all pre-existing skipped test identifiers must remain unchanged, and the module skip count may increase only from the frozen candidate count of 18 to 20. A separate display-backed run must execute both named methods with zero skips and pass; the other nine methods must also execute and pass, proving the assumption is scoped rather than a permanent bypass.

### B. Make the maximized-window test conditional on a proved window-manager capability

`GraphWorkspaceWindowModelShould.f11RestoresBoundsAndExtendedStateFromMaximizedWindow` depends on a window manager honoring `MAXIMIZED_BOTH`; a bare Xvfb display is not sufficient. Retain the existing headless guard and fullscreen round-trip assertions. The test reads `FREEPLANE_GRAPH_TEST_WINDOW_MANAGER` from its test-worker environment: its accepted values are `required` (the default) and `optional`; an unset value means `required`, and every other value is a hard test failure. Gradle's test worker inherits this environment variable, so no new build-level property propagation is involved.

Before requesting maximization, the test queries `_NET_SUPPORTING_WM_CHECK` on its current `DISPLAY` using `xprop`. A query/tool failure is an error, not evidence that a WM is absent. In `optional` mode, exactly one JUnit assumption skip is permitted only when the independent pre-maximize query proves `_NET_SUPPORTING_WM_CHECK` absent. If a WM is present, any missing `_NET_WORKAREA`, failure to maximize, or failure to stabilize is an assertion failure even in `optional` mode. In `required` mode, absence of either required EWMH property or failure to maximize is an assertion failure; it can never skip. Thus neither a maximize timeout nor a broken WM can be mistaken for the bare-Xvfb capability skip.

Keep the existing AWT-insets `workArea(graphics)` as the test's authoritative rectangle so the assertion preserves the existing `DisplayFixture` contract. Under a WM, read `_NET_CURRENT_DESKTOP` and that desktop's four-cardinal rectangle in `_NET_WORKAREA` on the same display, record both rectangles, and require their edges to agree within `X11_AWT_BOUNDS_TOLERANCE` (2 px); missing/malformed `_NET_WORKAREA` fails whenever a WM is present. The visible frame must cover the AWT work area within the same tolerance. Use the existing `awaitFrameStable(2100)` mechanism without enlarging its deadline: it polls every 10 ms, requires 2100 ms of continuous quiet, and fails at its existing 5000 ms monotonic deadline. Strengthen each poll to require the frame remains visible and displayable, `MAXIMIZED_BOTH` remains set, and the bounds remain unchanged; also require work-area coverage at the stable endpoint. Only then run the existing F11 round-trip assertions. The bare no-WM mode may skip before that interval only after proving the WM property absent; the required mode treats missing `_NET_WORKAREA` or a failed cross-check as failure.

The positive run has an explicit external prerequisite: Openbox release 3.6.1. Preflight records `command -v openbox`, `openbox --version`, `pacman -Q openbox`, and the executable SHA-256; on Arch, provision with `sudo pacman -S --needed openbox` and reject the run unless the reported upstream release is 3.6.1. If preflight cannot establish this prerequisite, emit `WM_PREREQUISITE_MISSING:OPENBOX_3_6_1` and block acceptance; do not call the WM run a skip or PASS. On an isolated Xvfb display, start `openbox --sm-disable` and wait no more than 5 seconds for the root `_NET_SUPPORTING_WM_CHECK` property. Verify the launched PID is alive and its `/proc/<pid>/exe` path and executable SHA-256 match preflight; require `xprop -root _OPENBOX_PID` to equal that PID. Read the support-window XID from `xprop -root _NET_SUPPORTING_WM_CHECK`; then require `xprop -id <support-XID> _NET_SUPPORTING_WM_CHECK` to self-reference the same XID and `xprop -id <support-XID> _NET_WM_NAME` to identify Openbox. Openbox 3.6.1 publishes `_OPENBOX_PID` on the root, not `_NET_WM_PID` on the supporting window; `_NET_WM_PID` may be recorded if supplied by a package but its absence must not reject stock 3.6.1, and the runner must not synthesize it. Record `_NET_CURRENT_DESKTOP` and `_NET_WORKAREA` too. The runner must use a cleanup trap, terminate and reap Openbox, allow `xvfb-run` to stop Xvfb, and record cleanup outcomes.

The bare run must show this exact test with one capability skip and the Openbox run must show it executed with `skipped=0`, `failures=0`, and `errors=0`. Both runs use isolated Xvfb and have separate receipts. The normal-window and other F11 tests remain covered independently.

### D. Resolve the lifecycle suite-order failure within the approved test-only boundary

The frozen baseline's full module suite failed once at `GraphWorkspaceLifecycleShould.doesNotDeliverCallbacksAfterClose` with `stale projection listener after close`, while the focused test passed. Preserve the invariant that no projection, canvas, or status callbacks are delivered after the coordinator's logical close boundary. First localize and record whether suite order exposes leaked fixture resources or a race-prone test assumption; do not infer a production defect from one order-dependent failure.

The governing [Graph Workspace Lifecycle Close-Boundary Remediation Design](2026-08-24-graph-workspace-lifecycle-close-boundary-remediation-design.md) authorizes changes only to `GraphWorkspaceLifecycleShould.java`; it explicitly forbids production-source, API, fixture-resource, build-configuration, timeout, or unrelated lifecycle changes. Follow its test-only barrier: prove the workspace map-lifecycle listener count rose above the captured `ResourceBaseline`, start close off the EDT and await the existing handle-closing rejection boundary, then wait with the existing bounded condition helper until the listener count returns to baseline before releasing the deliberately blocked first projection listener. Keep the current callback-registration rejection check only as a supporting observation, not as a substitute for this teardown signal. The return to baseline establishes that `GraphUpdateCoordinator` entered its logical closed state and began owned-map teardown. Preserve the second-listener zero assertion, source-map mutation, resource-baseline checks, callback counters, and closed-handle assertions. Release the blocking listener in a `finally` path covering the wait and bounded close-thread join so a failing probe cannot contaminate later tests.

Add no retries, sleeps, `Assume` guards, broad exclusions, or weakened callback-count assertions. Prove falsifiability in a disposable mutant by removing only the production closed-state guard immediately before each projection-listener invocation; the revised test must fail, and the active source tree must remain untouched. If investigation establishes that any production correction is required, stop and obtain a new explicit user decision before changing production code; this epoch's scope does not authorize one.

No lifecycle production source is authorized. If evidence requires production behavior changes, stop and obtain an explicit user decision. Also in scope are the final command/evidence records and the external, hash-recorded evidence runners under the PM run root.

Out of scope are changes to the approved `PREFERRED_NODE_GAP=24.0` ring-only behavior; relationship rest lengths; `ClusterPacking` gutter; convergence caps; idle thresholds; conflict-correction policy; any other performance golden or limit; unrelated lifecycle behavior; public APIs; and broad test-suite or harness redesign.
