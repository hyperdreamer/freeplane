# Task: Improve MCP subtree read outputs for agents
- **Task Identifier:** 2026-07-05-structured-read
- **Scope:** Improve MCP subtree read output for LLM/agent use. This
  task covers structured JSON node content from
  `readNodesWithDescendants` and compact agent-oriented plain text from
  `readNodesWithDescendantsAsPlainText`. Do not change map lookup,
  node selection, traversal depth, context-section request fields, or
  editing tools except where read DTO changes require compilation
  updates.
- **Motivation:** The subtree read tools feed LLM/agent context. JSON
  responses need structured fields instead of presentation labels.
  Plain-text responses need compact, useful context rather than empty
  bullets or redundant labels that spend tokens without helping answer
  the user's question.
- **Scenario:** An MCP client reads a selected subtree. JSON output
  exposes structured node `content`. Plain-text output uses the node
  text as the bullet title, labels only secondary fields such as
  details and attributes, omits irrelevant empty leaf nodes, and renders
  requested summary-structure qualifiers as semantic markers.
- **Constraints:**
  - Preserve the existing request contracts for both subtree read tools.
  - Preserve the structured JSON response contract from the completed
    JSON subtask, including `content` and no `unformattedText` field.
  - Preserve `readNodesWithDescendantsAsPlainText` as the compact text
    surface for LLM/agent context.
  - Do not add compatibility duplicates for removed or changed display
    fields.
  - Keep string content plain text, not HTML.
  - Do not change `fetchNodesForEditing`; raw editable text remains
    available there.
- **Briefing:** The MCP read tools are exposed through `AIToolSet` in
  `freeplane_plugin_ai`. `ReadNodesWithDescendantsTool` owns both the
  structured JSON subtree read and the compact plain-text subtree read.
  `NodeDepthItem` carries per-node read content and optional context
  sections such as qualifiers, hyperlinks, connectors, and clone
  metadata. `TextController.getShortPlainText(NodeModel)` already
  shortens summary text to 40 characters with continuation mark ` ...`.
- **Analysis:**
  - The plain-text read tool is an LLM/agent context surface, not a
    human-display surface.
  - Empty plain-text bullets are not useful context when they represent
    empty leaf nodes with no requested metadata.
  - The primary node text should be the bullet title; a leading
    `Text:` label is redundant when the bullet already denotes the
    node.
  - Secondary fields still need labels because otherwise details,
    notes, attributes, tags, icons, and metadata lose field meaning.
  - Empty summary-structure nodes are relevant only when their
    structure is requested or needed to preserve rendered hierarchy.

## Subtask: Return structured JSON content from subtree reads
- **Status:** review
- **Scope:** Rework `readNodesWithDescendants` so its JSON response
  returns structured node content instead of presentation-formatted
  `unformattedText`. Keep `readNodesWithDescendantsAsPlainText` as the
  compact labeled text surface. Do not change node selection, depth,
  context-section, map lookup, or editing tools except where they need
  to compile against the new response DTO.
- **Motivation:** The current JSON response can return
  `"unformattedText": "Text: example summary"` for a node whose raw
  text is `example summary`. That prefix is generated by the AI plugin,
  not by Freeplane core. In JSON this loses field boundaries, makes
  client parsing ambiguous, and misrepresents a display rendering as raw
  node text.
- **Scenario:** An MCP client reads a selected subtree. For nodes inside
  `fullContentDepth`, the JSON response exposes separate plain-text
  `text`, `details`, `note`, `attributes`, `tags`, and `icons` fields.
  For nodes outside `fullContentDepth`, the JSON response exposes only a
  `shortText` field. A client that wants display-oriented text calls
  `readNodesWithDescendantsAsPlainText` and receives the existing
  labeled tree rendering.
- **Constraints:**
  - Preserve the `readNodesWithDescendants` request contract.
  - Preserve the response envelope fields `mapIdentifier`, `items`,
    `nodes`, `omissions`, `parentNode`, and `breadcrumbPath` where they
    remain semantically valid.
  - Remove the JSON `unformattedText` node field instead of keeping a
    compatibility duplicate.
  - Use `content` as the JSON property for structured node content; do
    not use `unformattedContent`.
  - Preserve `readNodesWithDescendantsAsPlainText` output semantics,
    including labels such as `Text:` and `Details:` for full-content
    plain-text rendering.
  - Keep null fields omitted through the existing Jackson non-null DTO
    convention. Do not synthesize empty arrays for absent content.
  - Structured JSON content returned by `readNodesWithDescendants`
    remains plain text, not HTML. If a source field is HTML, convert it
    to plain text before assigning it to the node `content` field.
  - Do not change `fetchNodesForEditing`; raw editable text remains
    available there.
- **Briefing:** The MCP tools are exposed through `AIToolSet` in
  `freeplane_plugin_ai`. `ReadNodesWithDescendantsTool` owns the JSON
  subtree read, the plain-text subtree read, focus-node resolution,
  traversal, budget accounting, and read-tool summaries.
  `NodeDepthItem` is the per-node JSON DTO used by both subtree read
  variants. `NodeContentResponse` and its nested `*Content` DTOs are
  internal content-reader DTOs already used by other read/edit paths;
  they should not define the external JSON shape for this tool.

  - `ReadNodesWithDescendantsRequest` defaults `fullContentDepth` to
    `0`, so the focus node is read as full content by default.
  - `ReadNodesWithDescendantsTool.buildNodeDepthItem(...)` currently
    reads full content for nodes whose depth is within
    `fullContentDepth`; nodes beyond that depth use
    `TextController.getShortPlainText(...)`.
  - `TextController.getShortPlainText(NodeModel)` returns transformed
    plain node text shortened to 40 characters with continuation mark
    ` ...`, with node numbering disabled.
  - `TextualContentReader` converts full text, details, and note values
    to plain text with `HtmlUtils.htmlToPlain(...)` after applying
    Freeplane text transformations.
  - `NodeContentResponse.briefText` is an internal name for the short
    plain node text. Existing MCP selection responses use `shortText`,
    which is clearer for the external subtree JSON contract.
  - `buildUnformattedText(...)` turns structured `NodeContentResponse`
    fields into display lines by calling `appendLabeledLine(...)` with
    labels `Text`, `Details`, `Note`, `Attributes`, `Tags`, and
    `Icons`.
  - `appendLabeledLine(...)` creates the visible prefix with
    `label + ": " + value`.
  - Current attribute values are converted to plain text inside
    `buildUnformattedText(...)` with `HtmlUtils.htmlToPlain(...)`, so
    the structured JSON path needs to preserve that conversion instead
    of exposing formatted attribute markup.
  - `ReadNodesWithDescendantsToolTest` asserts current JSON values such
    as `Text: Focus full`, proving the label is part of the tool
    response contract rather than Freeplane node content.
  - `readNodesWithDescendantsAsPlainText` renders
    `NodeDepthItem.unformattedText` into the compact bullet tree, where
    the labels are appropriate presentation text.
  - Reusing `NodeContentResponse` directly as JSON content would expose
    internal wrapper fields such as `textualContent`,
    `attributesContent`, `tagsContent`, and `iconsContent` where the
    external response only needs flat content fields.
- **Analysis:**
  - `readNodesWithDescendants` returns structured content because JSON
    clients need field boundaries without parsing presentation labels.
  - `readNodesWithDescendantsAsPlainText` keeps labeled rendering so
    that display-oriented consumers still get compact readable text.
  - `NodeDepthItem` replaces `unformattedText` with `content` because
    keeping both fields would preserve the ambiguous JSON contract.
  - The `content` field uses a flat read-specific DTO because the
    `*Content` wrappers are internal reader/editor structure, not a
    useful external MCP response shape.
  - Structured content fields remain plain text because the existing
    subtree read contract exposes a plain rendering, not raw HTML.
  - Nodes outside `fullContentDepth` use `content.shortText` because
    the existing depth contract intentionally exposes shortened
    summary-only content for those nodes.
  - The conversion from internal content DTOs to flat JSON content
    happens at the read-tool boundary so shared content-reader and
    edit-tool DTOs do not absorb MCP response-shape concerns.
  - Attribute values need explicit plain-text normalization in the
    structured read path because the current label renderer owns that
    conversion.

## Subtask: Optimize plain-text subtree rendering for agent context
- **Status:** in-progress
- **Scope:** Rework only `readNodesWithDescendantsAsPlainText` rendering
  so its compact text output is more useful as LLM/agent context. Keep
  the structured JSON behavior from the completed subtask unchanged.
  Keep the plain-text response envelope and budget mechanism, but allow
  the rendered text format to change.
- **Motivation:** Current plain-text output can render `- Text: value`
  for ordinary node text and `-` or `-  [summary_node]` for empty
  structural nodes. For agents, those forms spend tokens and obscure
  which information is actually useful for answering the user's
  question.
- **Scenario:** For a selected subtree whose root text is `example
  summary` and whose visible children are `adfsdf` and `1`, the default
  plain-text output should be compact:

  ```text
  - example summary
    - adfsdf
    - 1
  ```

  If `QUALIFIERS` is requested for the same map shape, empty summary
  structure nodes should use semantic markers instead of empty bullets
  or raw qualifier names:

  ```text
  - example summary
    - [summary group start]
    - adfsdf
    - [summary]
    - [summary group start]
    - 1
    - [summary]
  ```

  Rich full-content nodes keep labels for secondary fields:

  ```text
  - Release plan
    Details: Prepare version 1.2 release.
    Attributes: owner=Alice; status=draft
    Tags: planning, release
  ```
- **Constraints:**
  - Do not change `readNodesWithDescendants` JSON output.
  - Do not change request parameters or add a new plain-text mode.
  - Do not render irrelevant empty leaf nodes in plain text.
  - Do not report semantically skipped empty leaves as budget omissions.
    Budget omissions remain about text budget exhaustion.
  - Preserve tree hierarchy when an otherwise empty node has rendered
    descendants.
  - Preserve existing labels for secondary content and metadata lines.
  - Preserve existing short-text truncation behavior and continuation
    mark from `TextController.getShortPlainText(NodeModel)`.
- **Briefing:** Current plain-text rendering is in
  `ReadNodesWithDescendantsTool.renderFocusNodeAsPlainText(...)`,
  `renderNodeContribution(...)`, and `renderPlainTextContent(...)`.
  Nodes are held as a preorder flat `List<NodeDepthItem>` with `depth`.
  Qualifiers are currently raw strings `summary_node` and
  `first_group_node` when `ContextSection.QUALIFIERS` is requested.
- **Research:**
  - Live MCP output for the selected map without `QUALIFIERS` included
    empty child bullets:

    ```text
    breadcrumbPath: example summary
    - Text: example summary
      -
      - adfsdf
      -
      -
      - 1
      -
    ```

  - Live MCP structured output with `QUALIFIERS` showed the empty child
    nodes were summary-structure nodes:

    ```json
    {"nodeIdentifier":"ID_1765161263","depth":1,"content":{"shortText":""},"qualifiers":["first_group_node"]}
    {"nodeIdentifier":"ID_1666677276","depth":1,"content":{"shortText":""},"qualifiers":["summary_node"]}
    ```

  - Live MCP plain-text output with `QUALIFIERS` currently renders raw
    qualifier names after an otherwise empty bullet:

    ```text
    - Text: example summary
      -  [first_group_node]
      - adfsdf
      -  [summary_node]
      -  [first_group_node]
      - 1
      -  [summary_node]
    ```

  - `TextController.getShortPlainText(NodeModel)` delegates to
    `getShortPlainText(nodeModel, 40, " ...")`, so summary-only node
    truncation already has an explicit continuation mark.
- **Analysis:**
  - A plain-text node line should first communicate the node's useful
    content. For a node with text, the text itself is the useful title;
    `Text:` adds no field boundary the bullet does not already provide.
  - Secondary fields require labels because they are not implied by the
    bullet marker.
  - Empty summary nodes and first-group nodes encode Freeplane summary
    structure. They should not appear in default compact text when they
    have no rendered content, but when qualifiers are requested their
    marker should use semantic words that help an agent interpret the
    map.
  - Empty leaf nodes with no rendered content and no rendered metadata
    should be skipped, not replaced with `[empty]`.
  - Empty non-leaf nodes must still preserve hierarchy. If they have no
    qualifier marker and no own rendered fields, render `[untitled]` as
    the bullet title rather than emitting a bare `-`.
  - Full-content node text is not shortened by this tool. If the text
    budget is exhausted, the existing omission mechanism should omit
    later nodes rather than partially render a full-content field.
- **Design:**
  - Change plain-text rendering only. `NodeDepthItem.content` remains
    the shared input for both read variants.
  - Replace `renderPlainTextContent(ReadNodeContent)` with a helper
    that returns ordered render lines:
    - primary title line: `shortText` or `text` without a `Text:` label;
    - secondary content lines: labeled `Details:`, `Note:`,
      `Attributes:`, `Tags:`, and `Icons:`;
    - metadata lines: existing labeled hyperlink, connector, and clone
      metadata lines.
  - Render the first available line on the bullet line. Render
    remaining lines indented under the bullet.
  - Convert qualifier names to compact semantic markers for plain text:
    - `summary_node` -> `[summary]`;
    - `first_group_node` -> `[summary group start]`.
  - If a node has a primary title and qualifier markers, append markers
    after the title on the same bullet line.
  - If a node has no title or secondary lines but has qualifier
    markers, use the marker text as the bullet title.
  - Skip a node in plain-text output when all of these are true:
    - it has no primary title;
    - it has no secondary content lines;
    - it has no rendered metadata lines;
    - it has no qualifier markers; and
    - it is a leaf in the rendered preorder range.
  - If an otherwise empty node has rendered descendants, render
    `[untitled]` to preserve the hierarchy instead of promoting
    descendants or emitting a bare bullet.
  - Determine whether a node has rendered descendants from the flat
    preorder list: the next node with greater depth means the current
    node has descendants in the rendered range.
  - Skipped empty leaves do not increment `renderedNodeCount`, do not
    consume text budget, and do not affect budget omission counts.
  - Keep short-text ellipsis behavior by continuing to use
    `TextController.getShortPlainText(NodeModel)` for summary-only
    nodes and by preserving returned short text exactly.
